# Contributing to Open Cities Lab projects

Thank you for your interest in Open Cities Lab (OCL)! We build open, reusable civic technology and digital public infrastructure with African governments and residents, and we welcome contributions from developers, designers, researchers, public servants and civic-tech communities.

This guide applies to every repository in the [`opencitieslab`](https://github.com/opencitieslab) and [`opendatadurban`](https://github.com/opendatadurban) organisations unless a repository has its own `CONTRIBUTING.md`.

## Ways to contribute

- **Report a bug.** Open an issue that describes what happened, what you expected and how to reproduce it.
- **Suggest an improvement.** Open an issue explaining the problem you're trying to solve, not just the solution.
- **Improve documentation.** Fixes to READMEs, setup guides and translations are very welcome.
- **Submit code.** See the workflow below.
- **Reuse our work.** If you're adapting one of our tools for another city or country, tell us! Reuse is the point. Email [hello@opencitieslab.org](mailto:hello@opencitieslab.org).

## Workflow for code changes

1. **Check for an existing issue** or open one to discuss larger changes before you start.
2. **Fork** the repository and create a branch from the default branch (e.g. `fix/ward-search-encoding`).
3. **Make focused changes.** Keep pull requests small and about one thing.
4. **Follow the existing style** of the project and add or update tests where the project has them.
5. **Don't commit secrets or personal data.** Many of our projects handle government and resident data; never include credentials, API keys or real personal information in code, fixtures or issues.
6. **Open a pull request** that describes what changed and why, and links the related issue.

A maintainer will review your pull request. We may ask for changes. Please be patient, as our team is small and works across many projects.

## Licensing

By contributing, you agree that your contributions will be licensed under the licence of the repository you're contributing to.

## Code of Conduct

Everyone participating in our projects is expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Security issues

Please **do not** report security vulnerabilities in public issues. See our [Security Policy](SECURITY.md).
